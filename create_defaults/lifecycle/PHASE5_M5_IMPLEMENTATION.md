## Reused boundaries and additive responsibilities

The original duplicate-key rejecting SafeLoader, closed definition loader,
Planner, lifecycle registry, current mapping replay, ReviewArchive attribution,
Phase 3 revalidation, CompositionArchive and owned worker receipts establish
source and native evidence. M5 does not replace them. Four additive modules
handle catalog spans, closed preparation values, complete publication planning
and append-only progress. The original Package E store, SQLite transactions,
immutable byte objects, events and CAS remain the only persistence mechanism.
There is no new database, SQL migration or alternate operational source parser.

OwnedCatalog always creates a new source fixture inside a concrete live
CompositionTrial. It seeds exactly the actual Genre catalog, profiles and lookup
from the current source checkout and binds commit/tree/Git blobs/raw SHA-256.
It accepts no arbitrary root, URL or writable production checkout. Stale commits,
dirty files, historical edits, unknown roots, unsafe modes and profile changes
fail closed. Output is a staged postimage; the source fixture is never modified
by preparation, and the production catalog is never a write target.

Only exact approved scalar spans or new complete assigned definition blocks may
change. UTF-8 offsets preserve BOM, CRLF, comments, order, unrelated text, IDs,
quotes and case. Existing YAML is never serialized wholesale. Compact lookup
JSON receives only exact member insertions and its checksum token; every
unrelated record remains unchanged. The original full Genre loader and Planner
must prove exact effective definitions and job delta before archiving postimages.
Profiles remain byte-identical. Lookup membership is mandatory for an ADD.

NativeSelection independently derives complete operation membership, current
entries, retained snapshot, review state and live attribution, Phase 3 pins,
translation/destination context and full native JPEG receipts. Complete required
members cannot be withheld or omitted by an operator manifest or transport batch.
Equal remote bytes still retain the required member and all currentness checks.
The existing validate_paths and batch_plan determine actual upload batches.

The immutable v1 preparation binds operation revision/event, native snapshot,
scoped heads, review, source observations, catalog postimages, destination tree,
all required member artifacts/receipts and exact original Package E plan. Closed
schemas and semantic membership/seal checks reject added authority fields,
substitution and omitted members. A sealed JSON value is never a grant.

Progress uses versioned immutable objects and append-only events in the original
store. Expected revision/previous SHA and scoped native/review heads are checked
under the original write transaction. Git work remains outside that transaction.
OS process leases exclude concurrent transports. PREPARED intent precedes Git;
INCOMPLETE and OFFLINE_VERIFIED require an actual local remote observation.
UNKNOWN cannot increase verified membership and retains bounded redacted failure
metadata. Cold replay opens the store read-only and reports integrity only;
fresh native/source/permission/target observations are mandatory before resume.

The original library_transport.run performs all local commits, pack measurement
and normal pushes to owned bare Git. Complete trees, blobs, modes, ancestry and
case/Unicode namespaces are independently reobserved. Recovery keeps successful
prefixes. Only exact owned next-batch dirty staging may be completed forward;
there is no reset, forced push, compensating delete or public overwrite.
The Windows autocrlf regression is prevented by the owned baseline fixture's
`* -text` .gitattributes, leaving all original dirty-worktree guards unchanged.

The dedicated draft code PR must identify baseline/final SHA, exact 27 paths,
inventory intersections, reused interfaces, byte/effective-job evidence, complete
bridge, bounded persistence/recovery, support matrix, native/local Git proofs,
all ten exact-head workflow runs and historical preservation. The static
acceptance file describes required evidence; it does not claim unexecuted CI.

Stop at a validated draft PR for maintainer review. Do not automatically merge.
