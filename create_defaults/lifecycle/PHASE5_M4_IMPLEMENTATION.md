## Current preimage and immutable lineage

Selection first uses the original M6 committed-state replay and pending-move
guard. It requires the exact current registry head and accepted definition,
stable identity, names, aliases and source hash. The original `resolve_stable`,
`StablePlanner`/`Planner` and `poster_candidate` independently reconstruct the
current English job and all category/font/layout/caption/source constraints.
Only assigned members can render; the historical library is never regenerated.

Before new source bytes can be staged, the adapter archives exact current YAML,
profiles and native input bytes as existing Package E `BytesObject`s and creates
a confined immutable before-input view in the owned `CompositionTrial`. This
new planning preimage reflects the committed rename; no old candidate, receipt,
artwork or registry epoch is edited. Native before planning is replayed from
those exact immutable bytes during recovery, without rendering historical art.
Its bounded cache keys freshly read bytes, not mutable paths or claimed flags.

The epoch binds selected entries/definitions, prior accepted snapshot IDs,
intervening mapping-plan hashes, current scoped dependency closure, exact native
before candidate/graph, registry head and input-object hashes. It is an audit
value, not authority. The transient prefix projector reads the same accepted
M1/M5/M6 journal, reuses M6's `MappingPlan`, `_ledger`, `_rename` and graph pruning,
and checks mapping bases/retained receipts before selecting a scope. No current
projection is persisted as another source of truth.

`propose_current` rejects a foreign/stale/tampered epoch before creating an
intent or composing. The proposed candidate is separately loaded from fresh
current definitions/source bytes through the original strict loader and planner.
UPDATE cannot change display/caption/source path/local/public mapping, semantic
identity, original names or category. It preserves all aliases and permits only
the existing registry API's exact addition of current names to retained aliases.
A same-path source-byte revision
uses the original registry API and preserves all prior registry snapshots.

## Native review, scoped CAS and recovery

Native default/requested JPEG composition, full member/source/renderer/font/
profile/layout verification, actual owned worker receipts, translation and
destination P3 consumption, and independent submitter/maintainer review all use
the existing consumers. A thumbnail, equal caption, self-signed hash, role flag,
old review or cached remote head cannot supply missing evidence or authority.

The original `Transaction.prepare` still verifies the native composition and
approved complete review. The new concrete wrapper additionally checks the
current accepted mapping/receipt lineage and full current consumer closure.
The existing atomic coordinator checks these under the same SQLite lock, applies
the same M1 read/write/namespace CAS, checks the expected prior snapshots, repeats
native review/attribution and final input/translation pins, and commits one new
snapshot plus an immutable lineage object/event. Unrelated identities/history
are never overwritten. Source/dependency changes with omitted consumers block.

Original M5 `require_m5_compatible` remains byte-identical. An old M5 candidate or
retry still rejects a member/dependency touched by M6. Only the exact concrete
current adapter can enter the new path; arbitrary subclasses/callbacks do not
qualify. New recovery permits a post-RENAME snapshot only when its exact lineage
has passed native replay against the journal prefix preceding that commit.
Missing lineage uses every original M5 preimage assertion; malformed, duplicated,
unpaired or mismatched lineage fails. M6 then accepts only the exact operation/
snapshot pair verified by native recovery and continues retaining old mappings.

Exact committed retries are integrity queries, never renewed authority. A crash
before COMMIT leaves no exposed snapshot/head; orphan immutable objects are
retained. A lost acknowledgement after COMMIT resolves to the same accepted
snapshot. Cancellation/revocation before commit rolls back. Cold restart uses
read-only journal/artifact verification and cannot reconstruct live grants.
Retirement after a current UPDATE retains its newest artwork/receipts and all
reserved aliases. No public delete or rename follows from local history.
