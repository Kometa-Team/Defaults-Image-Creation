## Authority design and readiness

All **22 exact contract approvals remain missing**. Every fresh-compatible
package reports COMPATIBLE, zero READY and zero ACTIVE. Default inspection,
without the fresh audit, explicitly says historical compatibility was not
freshly checked. Registry entries are still empty; no actual approval receipt
is created or fabricated.

The [operator/API guide](../bulk/contracts/activation/README.md) documents exact
fields, transitions, commands, transaction semantics and failure recovery.
The additive schema stores M1 approval companion envelopes, proposals, explicit
gate evidence, separate operator decisions and immutable revision chains.
Existing M1 records, Package E transactions/events and ContractStore blobs are
reused without migrations to production state or rewrites of old receipts.

There is no authenticated decision capture in existing Package E/M1–M6. Typed
`TrustedDecision` attribution is an external boundary, not a login mechanism.
M7 therefore **blocks operational integration** instead of treating supplied
JSON, a CLI name or a synthetic event as authentication. Future capture must
authenticate the current maintainer decision and revocation context, externally
select the exact approved registry and use unchanged M1 RegistrySnapshot for
every variant. The companion binds exact package/version/hash, registry, M1
receipt, review evidence, material compatibility, immutable event, UTC decision
time/expiry and authorization context.

An independent activation decision binds exact proposal/approval/gates and the
current runtime. Decision stages cannot substitute for each other or grant
publication authority. All prerequisites are explicit; their serialized status
is not itself trustworthy. The real adapter must derive them from actual M4/M5
owned evidence, full output/composition membership, source/dependency and
historical checks, current regressions and resolved exceptions.

Only explicitly synthetic contracts/principals/outputs can exercise ACTIVE in
M7. They cannot name implemented contract hashes, bypass the unavailable real
intake, activate production or publish artwork. Logo-only review cannot satisfy
a new poster's complete composition requirement. Numeric correspondence
automation remains uncalibrated/manual; no tolerance or D09 decision changes.

## Recovery, impact and security evidence

The same Package E transaction commits an M1 approval receipt, revision and
event atomically. Blob prewrites can leave harmless unreferenced objects after
an interruption. CAS prevents competing operators overwriting each other.
Every read verifies the chain and objects; activation revalidates current
context before writing and again inside the transaction. Revoked/expired,
wrong-package/category/source/registry, self-attributed, stale or incomplete
evidence cannot become READY/ACTIVE.

Restart/restored snapshots require a fresh runtime-specific operator decision.
Rollback appends SUSPENDED with an earlier exact proposal/registry selection,
retaining all intervening receipts/events. Revocation is terminal for the
stream. The guide contains recovery instructions for interruptions, corruption,
missing objects, source/registry changes, stale revisions and live journals.
An external anti-rollback checkpoint is absent; the system does not claim
cryptographic protection against a malicious whole-directory snapshot replay.
Real authority stays blocked, and restored ACTIVE data never grants runtime
authorization automatically.

M5 impact analysis reports exact affected categories, outputs and per-member
preview/confirmation/decision references. The Arrowverse logo affects exactly
its one poster and two overlays. The shared font probe demonstrates wider fanout;
unknown scope blocks readiness. Unchanged controls keep their own evidence.
Reports do not automatically revoke historical approvals or regenerate outputs.

Synthetic adversarial tests cover stage skipping, missing approvals, forged and
mis-scoped attribution, source/registry replay, missing companions, nested/style
or authority content, incomplete composition, forged publication authority,
separate operator permission, expiry/revocation, missing/corrupt blobs, chain
tampering, rollback, restart, actual process termination and simultaneous CAS.
Existing M1–M6 tests run alongside these: actual inherited/profile/generated-child
bypasses, opaque-source exceptions, stale previews and poster wash on overlays
continue to use their existing real validators, without weakened assertions.
